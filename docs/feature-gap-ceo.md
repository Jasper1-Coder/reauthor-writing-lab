# 功能缺口审计（CEO）· 从"展示层完善"回到"功能兑现"

> 结论先行：v0.9 把话说明白了，但 Eden 说的"功能不完善"是对的——有几处我们**对外承诺了、代码里也写了、用户却拿不到**，最典型的是"改写→申诉"的闭环是断的。本轮该补功能，不是再改文案。

## 一、当前真实功能清单（按"用户能不能拿到"重排）

| 能力 | 状态 | 说明 |
| --- | --- | --- |
| 贴文/拖文件分析、五维评分、逐句批注 | 可用 | 核心引擎稳，`Analyzer.tsx:91` |
| PDF/DOCX/PPTX/TXT/MD 本地导入 | 可用 | 扫描版 PDF 提示手粘，合理 |
| 校准模型 / 语料检索 / 跨域 / 红队 | 可用但藏深 | 全在默认折叠的 `<details>`（`Results.tsx:252`），检索还要手动点启动 |
| 改写工作台：自己改+即时复测+导出对照表+回填重测 | 可用 | 草稿存 `localStorage`（`RewriteWorkbench.tsx:32`） |
| 申诉工作台：录平台分歧→一页纸→导申诉信 | **部分可用** | 见下方缺口，第 3 条证据与第 5 节经常空 |
| 7 条公开可引用证据（斯坦福误报等，带出处） | **UI 已不可达** | `buildDefenseDocument` 只剩测试在调（`defense.ts:28`） |
| 一案一证申诉证据包 | **入口断了一半** | `buildAppealPacket` 支持 `rewriteEntries`，但 `DefenseKit.tsx:83` 调用时没传 |
| 报告历史 / 改前改后并排对比 / 过程留痕 | **没有** | 报告只在内存，刷新即丢 |

## 二、承诺 vs 兑现：第一性原理审计

我们的口号是"**别人判你像不像 AI，我们帮你把文章改成你自己的**"；首页卖点是"每句能点开看依据 / 自己改立刻看变化 / 原稿不离开电脑"；方法页立场是"诊断必须通向行动"。逐条对账：

| 对外承诺 | 兑现度 | 具体缺口 |
| --- | --- | --- |
| "改成你自己的"→ 改写要能变成可拿走的证据 | **半兑现** | 改写稿只存在改写台自己的 localStorage；进申诉信的通道是断的（见下），学生改了半天，申诉信里第五章还是"（可选：附上对照表）"占位符。`appealPacket.ts:163` 取 `userInput.rewriteEntries`，而 `DefenseKit.tsx:83-92` 的入参里根本没有这个字段——只有测试里手动传过。 |
| "给老师的一页纸 · 本案三条最强证据" | **经常只有两条** | 第三条证据在检索没跑时回退到"改写记录"，而改写记录又永远为空（`DefenseKit.tsx:48-50`）。检索入口藏在折叠区技术面板里，多数学生不会展开→第 3 条几乎永远显示"尚未附上"。 |
| 申诉工作台"7 条可引用的公开证据" | **界面上看不到了** | v0.8 用 `buildAppealLetterMarkdown` 替换了 v0.4 的 `buildDefenseDocument`，后者（含全部证据+出处链接）现在只被测试引用；新申诉信里只剩硬写的机关名称，没有可核查的出处。B 类学生最需要的"这个百分比为什么不能全信"的外部权威，反而没了。 |
| "诊断通向行动""最短成功路径三步" | **第 3 步打结** | 改后全文要"复制→粘回→重新分析"靠剪贴板往返；原报告在 `App.tsx:9` 是单一 state，重测后旧报告被覆盖，根本没有"两份报告并排看"的能力。 |
| "原稿不上传 / 隐私" | **完全兑现** | 这是护城河，别动。 |
| "不确定就弃权" | **兑现但太一刀切** | 样本不足直接不产出申诉信（`appealPacket.ts:112`）；一篇 300 字的课程作业被判了，恰恰最需要申诉，却什么也给不了。 |

一句话：**技术能力一件没少，但能力之间的"管子"接错了、或根本没接。**

## 三、对照战略文档：最短成功路径的三处断点

战略文档 `ceo-strategy-v2.md:118-132` 定义三步：贴进来 → 看懂三句话 → 拿到一个结果。逐段看现在被打断在哪：

1. **贴进来**：`Analyzer.tsx:134-148` 默认要先选"文档类型/语言"，`documentType` 默认 academic；跑分析还有 4 段共约 1 秒的人造进度动画（`Analyzer.tsx:95-98`）。战略文档要求的"30 秒内开始、不要先做填空题"没做到。
2. **看懂三句话**：v0.9 已把技术黑话收进折叠区，这一步基本通了。但"最可疑的几句"是夹在全部句子里按原文顺序排的，只有"需复核"筛选，没有把 3 句最高分的自动顶到最前。
3. **拿到一个结果**：这是最严重的断点。改写要手动剪贴板往返、改前改后无法并排、申诉信丢掉改写证据与公开出处、短文本直接锁死。**学生走完三步后手上拿不到那份"能交给老师的东西"。**

## 四、竞品视角：学生羡慕、而我们能合理补的

- **Grammarly 的实时改写建议**：学生爱它"不做判官、真的帮忙改"。可借鉴的是**即时反馈的姿态**，不是它的 AI 代写。我们可补"边写边提示哪句是套话、缺证据"，但只提示、不替写——绝不碰"一键降 AI 率"。
- **Turnitin 的过程留痕**：学生羡慕的是"我有证据证明这是我一步步写的"。我们恰好可以站在学生这边反向实现：**本地自动记录每次分析与改写的时间线**（不是给学校装监控）。完全不违背"不证明身份"——它只是学生自述的辅助材料，不替他作证。
- **GPTZero 的共享报告链接**：可借鉴"一键交给老师"。但做成服务端链接就要上传原稿，撞我们的隐私红线。**替代方案是导出一份离线自包含 HTML/打印版**，既能发又能不上传——这是我们能合理补、且不骗人的版本。

不抄的：任何"判罚面板""准确率宣称""身份判定"。

## 五、功能完善优先级清单

### P0 — 本轮必须做（最贴合立意，都是"承诺没兑现"）

**P0-1 打通「改写 → 申诉」数据链**
- 缺口：改写草稿在 `RewriteWorkbench` 的 localStorage（key `reauthor-rewrites-v1:<createdAt>`），`DefenseKit` 完全没读；申诉信第五章永远是占位符，一页纸第 3 条证据也因此常常缺席。
- 学生为何需要：B 类学生被判后，最有力的材料就是"我把空话改成了自己的论证"这份真实轨迹。现在这段努力在申诉环节蒸发。
- 做成什么样：`DefenseKit` 按同一 `createdAt` 读出该报告的改写草稿，转成 `RewriteEntry[]` 传给 `buildAppealPacket`；一页纸第 3 条在无检索时回退到真实的"改写 N 句"而不是"尚未附上"。
- 红线：数据全部来自学生本人真实改写，只做搬运、不生成、不虚构；仍标注"不构成作者身份判定"。

**P0-2 把「7 条公开证据 + 出处」接回申诉材料**
- 缺口：`DEFENSE_EVIDENCE`（斯坦福 61.3% 误报、同文异判、OpenAI/范德堡停用等，均带来源 URL）在 v0.8 后从 UI 掉线，只剩硬编码结论。
- 学生为何需要：申诉信的说服力来自"可核查的外部证据"，不是我们的自述。老师要能点开出处。
- 做成什么样：在 `buildAppealLetterMarkdown` 增加一节"公开可查证的检测器可靠性证据"，逐条带标题/数据/来源；一页纸也引用其中 1–2 条。
- 红线：只如实引用公开研究/报道并标出处，不宣称"证明清白"、不保证申诉成功。

**P0-3 让「改前/改后」两份报告能并排看（最小版过程留痕）**
- 缺口：`App.tsx:9` 只有一个 `report` state，回填重测后原报告被覆盖，没有历史、没有对比。
- 学生为何需要：口号说"亲手改一句立刻看到变化"，但现在只能看到单句的即时复测，看不到**整篇**改前改后的差异——而这正是 Turnitin 留痕让学生羡慕的东西。
- 做成什么样：保留最近两份报告（原稿/改后），在结果页加一个"对比上次"视图，展示总分、各指标、分歧度的前后变化；全程本地。
- 红线：对比只呈现同一公开规则下的读数变化，明确"降分≠改好"，不替学生证明作者身份。

### P1 — 下一轮

- **P1-1 边写边提示**（不做代写）：输入框旁轻量提示"本句命中套话/缺具体证据"，不打分不判罚。镜像 Grammarly 的姿态。红线：只提示，不提供一键改写。
- **P1-2 短文本也能申诉（降级版）**：不足 400 字时，不给"本案读数版"申诉信，但可给"仅用公开证据 + 学生自述"的模板，并明确"未使用本报告读数"。红线：不拿不够格的读数去申诉。
- **P1-3 申诉页直接补检索证据**：在申诉台加"一键运行检索补全第 3 条证据"，别让学生去折叠区翻。红线：覆盖率低仍如实标定性参考。
- **P1-4 导出离线单文件 HTML 报告**：可发给老师、可打印，不上传服务器。红线：走本地导出，不做服务端共享链接。
- **P1-5 贴进来少做填空题**：文档类型/语言收进"更多设置"，默认自动识别，去掉人造等待。纯功能体验，不动伦理。

### P2 — 想想就好

- 服务端共享报告链接（撞隐私红线，除非用户明确授权上传；优先用 P1-4 替代）。
- AI 使用声明标准化勾选生成器（帮学生**如实**声明，不能变成规避话术）。
- 扫描版 PDF 本地 OCR（重，且本地化处理质量难保证）。
- 班级/教师协作面板（绝不做判决面板，只做"学生主动分享"的对话视图）。

## 六、CEO 本轮拍板建议

**只做 2–3 项的话，我做 P0-1、P0-2、P0-3，顺序即优先级。**

- P0-1 是**真 bug**：我们承诺的闭环在数据层是断的，修它成本最低、兑现最直接——"改写权"如果传不到申诉信，口号就只兑现了一半。
- P0-2 恢复的是我们**最独特的可信资产**：别家有分数，我们有带出处的公开证据。把它从死代码里捞回来，是零伦理风险的高价值动作。
- P0-3 补的是**最短成功路径的第 3 步**："拿到一个结果"。学生改完能并排看到整篇变化，才真的"把文章改成了自己的"。

三者都不碰判罚、不证明身份、不保申诉成功，全部站在学生这边。本轮**不加**任何"降 AI 率"或代写式功能——那不是完善，是背叛定位。
