# CEO 战略简报 · 本轮唯一聚焦

> 团队正式交接文档，供 PM 拆需求、开发与测试逐条引用。
> 项目：ReAuthor · 重写权（v0.7.1）
> 立场：学生视角、可解释、公开误差、帮学生有据可依地对抗不合理的 AI 查重判决。

---

## ① 本轮唯一聚焦 + 第一性原理理由

**唯一方向：做"一案一证"的申诉证据包。**
把申诉工作台从当前的"通用证据库 + 空模板 + 用户自填多平台分数"，升级为**针对本文、由现成诊断数据自动填充、可一键导出的申诉 / 答辩信**。

**第一性原理推理：**

1. 学生是**拿着一份已经被判"高 AI 率"的论文**来找我们的——写作此时已完成，无法回头补"写作过程留痕"。他能打的仗只剩一场：质疑判决本身。
2. 质疑判决最有力的武器，不是人人都一样的通用研究引用（斯坦福 61.3% 误报、同文异判报道等，老师见过一次就不买账第二次），而是**"我这篇文章，用你们的方法多测几遍，结果自相矛盾 / 跨领域失效"的本文实证**。
3. 这些实证本站**已经算好了**：多通道分歧度、跨域阈值塌缩、校准模型边界、检索匹配度低、改写前后对照——但散落在报告的各类面板里，学生看不懂、也不会用；而申诉工作台又只给了空模板，他填不出内容。
4. 因此最大、最可被用户感知的价值缺口，是把"已算好的本文证据"接成一份学生能直接交给老师 / 教务的材料。这不是新增指标，而是把现有能力兑现成行动——与产品立场"检测必须通向行动""帮学生有据可依"完全一致。

## ② 具体功能点（5 个，开发可直接动手）

### 功能点 1 · 新增纯函数证据装配器
- **文件**：新增 `src/lib/appealPacket.ts`
- **职责**：纯函数，入参 `report: AnalysisReport` + 检索结果（可选，`RetrievalChannelResult`）+ 用户填写的多平台分数，输出结构化的"申诉证据包"数据。
- **输出结构（6 个板块）**：
  1. 判决概况（被判平台、分数、本站读数）
  2. 本文多通道分歧实证（各通道分数 + 分歧度数值 + "任何单一百分比不可引用"的口径）
  3. 跨域阈值失效说明（引用 `crossDomainValidation.json` 的真实数字）
  4. 检索匹配度 / 最近邻
  5. 改写前后对照（复用 `buildRewriteComparisonMarkdown` 的数据源）
  6. 写作过程自述占位（如实填写，占位符不预填内容）
- **约束**：只组织已有数据，**不新增、不修改任何评分口径**；不 import 任何联网 / AI 依赖。

### 功能点 2 · 改造申诉工作台为"证据装配台"
- **组件**：`src/components/DefenseKit.tsx`
- **交互**：从"静态证据列表 + 空表单"改为**分步骤引导式装配**，每一步自动带入本报告真实数据，学生只需补充只有他本人知道的信息。
- **文案口径（示例）**：
  - 步骤二自动写入："本站对本文跑出 6 条独立读数：{列出各通道分数}，通道分歧度为 {N}。按本站公开口径，此分歧下任何检测网站给出的单一百分比（包括本站）都不应被引用。"
  - 步骤三自动写入："本站校准模型训练于问答语料，在真实学术摘要跨域测试中绝对分数塌缩至 0–18、阈值 50 灵敏度为 0%（可复现：`npx tsx scripts/crossdomain-test.ts`）。"
  - 学生自填项只保留：被判平台的名称与实际分数、本人写作过程自述（强制如实，明确拒绝代写与虚构）。
- **伦理红线**：装配台显著位置常驻"不证明作者身份 / 不保证申诉成功 / 请如实填写"。

### 功能点 3 · 一键导出 filled-in 申诉 / 答辩信
- **文件**：`src/lib/report.ts`
- **职责**：新增 `buildAppealLetterMarkdown(packet)`，导出一份**已填充的中文申诉 / 答辩信**，而非空模板。
- **必含内容**：本文实际通道分数、分歧度数值、至少 1 条指向本站公开证据 / 可复现管线的脚注（如 `calibratedModel.json`、`crossDomainValidation.json`、`scripts/train-model.ts`）、写作过程自述占位符。
- **复用**：沿用现有 `buildMarkdownReport` / `buildRewriteComparisonMarkdown` 的导出样式与 `downloadText` / 剪贴板路径，不引入新导出机制。

### 功能点 4 · 顶部"给老师的一页纸"
- **组件**：`src/components/DefenseKit.tsx`（或作为独立子组件）
- **交互**：证据包顶部生成一张卡片——**3 条本文最有力的证据 + 2 句学生可直接念的回应话术**，降低当面对质时的开口门槛。
- **文案口径**：客观、克制、可被老师复核；话术示例："这篇文章我用本站做了多通道复核，六个读数互相矛盾，我希望能一起看证据，而不是只看一个百分比。"

### 功能点 5 · 测试
- **文件**：`src/test/` 下为 `appealPacket.ts` 补纯函数单测。
- **覆盖**：填充正确性（给定 report 输出预期字段与数值）、空数据 / 样本不足降级、伦理红线文案存在性、导出信必含字段。

## ③ 明确不做什么

- **不加**任何新的检测指标 / AUC / 模型 / 训练流程。
- **不动** `src/lib/analyzer.ts`、`src/lib/calibrated.ts`、`src/lib/retrieval.ts` 的评分逻辑与常量。
- **不调 AI、不联网**：所有填充来自本地已有数据 + 用户如实填写，不引入模型或网络请求。
- **不伪造过程证据**，不宣称本工具能"证明作者身份"或"保证申诉成功"。
- **不做**后端 / 账号 / 云存储；不破坏"纯静态可发布 gh-pages"的形态。
- **不重复造轮子**：不新增导出机制、不重写已有报告 / 改写对照的数据源。

---

## ④ 测试可验证的验收标准

1. 给定一份含**多通道分歧**的 `report`，`buildAppealLetterMarkdown(packet)` 输出的申诉信必须包含：本文实际的通道分数、分歧度数值、≥1 条指向本站公开证据 / 可复现管线的引用、写作过程自述占位符。
2. `DefenseKit` 默认视图展示**自动填充的证据**（非空表单）；用户补充多平台分数后，可导出完整、可直接使用的申诉信。
3. **样本不足**（短文本 / 不足 6 句）场景：证据包降级为"仅规则观察、不构成申诉依据"文案，不产出可用的申诉信。
4. "给老师的一页纸"卡片包含 3 条本文证据 + 2 句回应话术，且不含任何"保证成功 / 证明身份"的断言。
5. 全量测试（**≥21 项**）通过，且 `npm run check`（eslint + vitest + tsc + vite build）通过。

---

## ⑤ 风险 / 约束

- **伦理红线（硬约束）**：所有对外文案必须带"不证明作者身份 / 不保证申诉成功 / 如实填写"口径，防止工具被当作"洗白作弊"的挡箭牌。
- **一致性风险**：不可因强调"检测不可靠"而削弱本站自身可信读数（校准模型域内 AUC 0.930 等）；证据包的批评口径必须与现有"诚实披露"保持一致，针对的是"任何单一百分比判决"而非本站全部能力。
- **技术约束**：不破坏现有 21 项测试；保持本地隐私、零 AI 依赖；纯静态可发布到 gh-pages；不引入需要后端的形态。
- **体验风险**：自动填充不得喧宾夺主变成"又一张看不懂的图表"——须始终以"学生能直接交给老师"为验收锚点。
